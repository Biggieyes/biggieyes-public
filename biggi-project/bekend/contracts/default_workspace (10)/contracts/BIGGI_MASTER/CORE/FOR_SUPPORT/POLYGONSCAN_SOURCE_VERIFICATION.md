```text

```

The Hardhat config uses Etherscan API V2 style verification. `POLYGONSCAN_API_KEY` is legacy for this setup and is not the primary key used by the current config.

## Commands

Compile:

```powershell
npm run compile:master
```

Build deployment manifest:

```powershell
npm run manifest:deployment:polygon
```

Audit public PolygonScan name tags:

```powershell
npm run audit:master:polygonscan-tags
npm run audit:master:polygonscan-tags:retry
```

Public name tags are independent of source verification and require PolygonScan
account ownership verification plus PolygonScan review. The prepared submission
is `POLYGONSCAN_PUBLIC_NAME_TAG_SUBMISSION.md`.

Verification helpers:

```powershell
npm run verify:master:visibility:polygon
npm run verify:master:tokenomics:phase1:polygon
npm run verify:master:tokenomics:phase2:polygon
npm run verify:master:core-series:sources:polygon
npm run verify:master:cre-receiver:polygon
```

CRE preflight:

```powershell
npm run preflight:master:cre:polygon
```

Mainnet preflight:

```powershell
npm run preflight:master:polygon
```

## Sourcify Note

During the latest receiver verification pass, the Sourcify API v1 endpoint returned `503 Service Unavailable`, while PolygonScan already showed the contract as verified. A PolygonScan-only re-run succeeded with:

```powershell
$env:DISABLE_SOURCIFY_VERIFY='1'
npm run verify:master:cre-receiver:polygon
```

This is documented as an external Sourcify availability issue, not as a PolygonScan source verification failure.

## Manual Verification Fallback

If PolygonScan support requests manual material, use the Standard JSON input generated by Hardhat artifacts/settings for the exact deployed contract. Do not use flattened sources unless PolygonScan explicitly requests that format.
